# Local control plane

Machinist's optional control plane adds a browser UI, SQLite-backed queue, durable
run history, and worker redispatch to the same runner used by direct mode.

This release is local-only. The server rejects non-loopback listeners.

## Configure a repository

`machinist init` creates the server and worker settings. Add at least one named
repository to `~/.machinist/worker.toml`:

```toml
data_directory = "~/.machinist/worker"

[control_plane]
url = "http://127.0.0.1:7331"
token_file = "~/.machinist/server/worker.token"

[repositories.machinist]
path = "/absolute/path/to/machinist"
```

The worker token is generated by `machinist init`. The server and worker must
reference the same token file.

## Run the scheduled merge queue

The shipped `shepherd` agent can inventory all open pull requests and process the opted-in
queue on a schedule. Configure a schedule with the worker's logical repository name:

```toml
[shepherd.machinist]
repository = "machinist"
every = "30m"
max_actions = 3
```

The server admits the first run at startup and persists later due times. A database guard
prevents overlapping Shepherd runs for the same repository, including across server
processes using the same database. Scheduled jobs use the same durable queue and worker
lease protocol as manual submissions.

Shepherd changes only pull requests carrying `machinist:auto-merge`. It processes them
serially, refreshes the queue after each merge, and leaves blocked or deferred evidence on
the affected labelled pull request. A pending stack retarget is recorded before its parent
merges, so restart recovery remains safe even when `max_actions = 1`. The default `foreman`
remains unable to merge.

## Start the server and worker

Start the control plane:

```sh
machinist start
```

Start a worker in another terminal:

```sh
machinist worker start
```

Open [http://127.0.0.1:7331](http://127.0.0.1:7331). The server owns the job
queue and agent definitions. The worker advertises its executor names,
repository names, and model aliases, then accepts one compatible run at a time.

Node.js is not needed at runtime. The React application is embedded in the
Machinist binary.

## Submit from the CLI

The browser and `machinist submit` use the same managed queue. Pass the configured
repository name, not its worker-local path:

```sh
machinist submit \
  --agent=foreman \
  --repo=machinist \
  --prompt="Complete https://github.com/example/project/issues/123"
```

Submit reads the control-plane URL and bearer-token path from `worker.toml`,
checks the repository and selected agent or pipeline against the server's
catalog, queues the job, and prints its ID. Use `machinist run` when you want to
execute immediately without contacting the control plane.

## Ownership boundary

The server sends a worker only:

- run, job, agent, and definition identifiers;
- a rendered prompt;
- an executor name and optional model alias;
- a repository name;
- a timeout; and
- an opaque run lease.

It never sends executable commands, local paths, environment variables, or
credentials. The worker resolves all machine-local details and rejects unknown
names before starting an agent.

## Security boundary

The local web surface has no user authentication, so Machinist enforces its local
boundary:

- the server accepts loopback listen addresses only;
- browser submissions require a process-local CSRF token and matching loopback
  Host and Origin headers;
- worker endpoints require the bearer token created by `machinist init`; and
- workers allow plain HTTP only for loopback control-plane URLs. Non-loopback
  URLs require HTTPS.

Do not expose the control plane through a port forward or reverse proxy without
adding an authenticated human web surface and a TLS boundary.

## Leases and redispatch

A worker receives one run with an opaque lease token. The lease lasts 30 seconds
and the worker renews it every 10 seconds while the process runs and while it is
delivering the result.

Polling requeues an abandoned run after its lease expires. A compatible worker
can then receive a new token and execute a new attempt. The stale worker may
finish locally after losing connectivity, but it cannot renew or upload with the
old token.

This recovers abandoned work. It does not provide exactly-once agent side
effects or resume an interrupted process. Separate attempt directories preserve
the artifacts from both executions.

Completion is idempotent for the active lease. If the database commit succeeds
but the response is lost, the worker can send the same completion again without
advancing a pipeline twice.

## Persistence

SQLite stores jobs, ordered runs, workers, terminal results, and completed event logs. It
also stores the next due time for every Shepherd schedule. The default database is
`~/.machinist/server/machinist.db`. Restarting the server against the same database restores
that state without repeating a not-yet-due scheduled run.

For protocol details, invariants, and acceptance criteria, read the full
[control-plane design](control-plane/design.md).
